# 全项目逆向与故障恢复 SOP

这份 SOP 定义 Feishu Codex Console 在安装、连接、项目、会话、任务、审批、团队协作、数据和发布任一步失败时必须怎样表现和恢复。它不是错误码列表，而是产品的失败契约：**错误必须可见、状态必须可恢复、成功步骤不得重复、权限不得悄悄扩大。**

正常流程见 [全项目正向 SOP](USER_SOP.md)，总入口见 [SOP 总览](SOP_INDEX.md)。

## R00：任何故障都先执行的六步

### 1. 判断是否需要止损

出现下面任一情况，先停止继续操作；如果任务可能继续产生副作用，再停止对应任务或 Bridge 服务：

- 项目、成员或会话明显不对；
- 同一任务、群或外部动作疑似被执行两次；
- 文件继续被意外修改；
- 凭据可能出现在飞书、日志、Diff 或支持包；
- UI 显示成功，但本机或飞书远端事实不一致；
- SQLite 完整性、迁移或备份校验失败。

停止任务不代表撤销文件。停止服务前先记录任务 ID、项目、会话、卡片时间和用户可见现象；不要复制秘密正文。

### 2. 确定影响级别

| 级别 | 判定 | 处理要求 |
|---|---|---|
| S0 安全事件 | 凭据泄漏、越权执行、外部破坏性动作、项目串线 | 立即止损、撤销凭据、保留脱敏证据、阻断发布 |
| S1 数据/重复执行 | SQLite 损坏、重复任务/群/发布、错误项目写入 | 停止相关执行，先恢复权威状态再重试 |
| S2 功能不可用 | 设备离线、Codex 不可用、事件断开、升级失败 | 按最小失败步骤恢复，不扩大权限 |
| S3 展示降级 | 卡片更新失败、额度不可用、非关键置顶失败 | 保持真实状态，用可靠文本或待修复状态降级 |

### 3. 按权威顺序取证

```text
用户看到的飞书消息/卡片
  → Bridge 健康文件和 status/doctor
  → SQLite 中的项目、会话、任务和补偿步骤
  → 本机项目、Git、文件和 Codex thread
  → 飞书远端群、成员、消息和置顶对象
```

卡片不是最终事实。任何“已完成”都必须同时得到本地状态和必要远端对象支持。

### 4. 只修复最小失败步骤

群已创建就不再建群，工作台已发送就只重试置顶，任务已启动就不自动重放，确认已消费就不重新消费。不要为了恢复一个展示错误而删除用户文件、重建群或重置数据库。

### 5. 重新鉴权或重新确认

排队任务、外部动作、运行时审批、任务交接和完全访问租约在恢复前都重新检查成员、项目 ACL、仓库策略、sandbox、有效期和所有者。

### 6. 关闭故障

至少记录：故障编号、影响对象、根因、修复动作、备份 ID（如有）、恢复时间、无重复/无越权证明和仍需人工处理的事项。

## 全局禁止事项

- 不因不确定意图默认写文件或运行命令。
- 不把停止任务描述为已经撤销修改。
- 不自动重放已启动或状态不明的任务。
- 不静默切换项目、thread、模型、成员或权限。
- 不在已有绑定后创建第二个项目群。
- 不在已有 `workspace_message_id` 后重发第二张工作台。
- 不把累计 token 推算为账户额度。
- 不把 Codex turn 完成推断为测试通过。
- 不通过飞书接收密码、Token、验证码、私钥或其他秘密。
- 不用 `doctor --fix`、升级或卸载删除用户项目文件。
- 不把未脱敏数据库、日志或支持包上传到公开 Issue。

## 1. 安装和首次连接失败（N01～N05）

| 编号 | 触发条件 | 用户应看到 | 禁止副作用 | 恢复动作 |
|---|---|---|---|---|
| N01 | Bot 身份不可用 | 安装阻断，提示重新绑定应用 | 不写“安装完成” | 运行 `npx lark-cli config init --new`，验证 Bot 后重跑 |
| N02 | 消息或卡片事件缺失 | 安装阻断并列出缺失事件 | 不启动一个无法交互的服务 | 补事件、发布应用版本、重新探测 |
| N03 | 项目群增强 scope 无法读取 | 显示“当前无法确认”，私聊仍可用，并提供一键配置命令 | 不伪装为“已验证” | 运行 `configure-feishu --profile project-chat`；完成普通消息实测 |
| N04 | 项目群增强 scope 明确缺失 | `doctor` 列出缺失能力和一键配置命令 | 不阻断纯私聊，不宣称自动建群可用 | 官方页面确认、按需发布版本、只重试失败步骤 |
| N05 | 项目不存在、路径不可访问或 Codex 未登录 | 安装/doctor 失败并给下一条修复动作 | 不保存无效项目、不放宽目录权限 | 修复路径/扫描根、完成 `codex login` 后重跑 |

## 2. 已有群首次绑定失败（N06～N13）

| 编号 | 触发条件 | 用户应看到 | 状态要求 | 恢复动作 |
|---|---|---|---|---|
| N06 | 非管理员在未绑定群发消息 | “请管理员完成首次绑定” | 不加可信列表、不落绑定、不入队 | 管理员在群里发送 `项目` |
| N07 | 非管理员点击绑定控件 | “只有管理员能绑定” | 与 N06 相同 | 管理员操作原卡 |
| N08 | 绑定卡无法创建或回复 | CardKit/事件修复提示 | 不展示不可执行的文字切换入口 | 修复 CardKit 后重新发送 `项目` |
| N09 | 所选项目已绑定其他群 | 显示已有项目群冲突 | 当前项目、可信列表和绑定不变 | 进入已有群，或选择其他项目 |
| N10 | SQLite 绑定写入失败 | “绑定失败”及脱敏原因 | 不同步群项目、不加入可信列表 | 修复数据目录/SQLite 后重试 |
| N11 | 绑定已写入但会话同步失败 | “绑定已保存，初始化待修复” | 绑定保持不可变并记录失败步骤 | 再发 `项目` 或打开工作台触发自愈 |
| N12 | 工作台更新/发送失败 | “绑定已保存，工作台待修复” | `workspace_status=failed`，不解除绑定 | 修复卡片能力后补发工作台 |
| N13 | 置顶失败 | “工作台可用，置顶待修复” | 保留原 message ID，`pin_status=failed` | 只重试 pin 原消息 |

## 3. 自动创建项目群失败（N14～N21）

| 编号 | 失败点 | 必须保留的状态 | 再次操作 | 绝对不能做什么 |
|---|---|---|---|---|
| N14 | 缺少 `im:chat:create` | 不产生虚假绑定 | 补 scope 后用同一确定性 UUID 重试 | 显示群已创建 |
| N15 | 飞书已建群，本地绑定写入失败 | 远端确定性 UUID | 用同一 UUID 找回同一群并补绑定 | 换 UUID 再建一个群 |
| N16 | 邀请成员部分或全部失败 | `members_status=failed/partial` | 只同步缺失且仍有 ACL 的成员 | 删除已可用群、重复邀请成功成员 |
| N17 | 工作台创建/发送失败 | 绑定和群保持，message ID 为空 | 只创建并发送工作台 | 再次建群 |
| N18 | 工作台 message ID 已保存后进程停止 | workspace 成功、pin pending | 重启后只 pin 原 message ID | 再发一张工作台 |
| N19 | 置顶失败 | `pin_status=failed`、原 message ID | 只重试 pin | 重发工作台 |
| N20 | 私聊群入口发送失败 | 三步 setup 状态不变 | 只重发群入口 | 把项目群标失败或重建群 |
| N21 | 并发点击或 callback 重放 | 项目级 single-flight 和幂等结果 | 所有请求返回同一群 | 调用两次 create |

## 4. 意图、任务与基础权限失败（N22～N29）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N22 | 没有可匹配上下文，只发“继续” | 回退只读，不继承其他项目/成员/thread | 在正确回复串重发完整目标 |
| N23 | 明确“不要修改/不要执行” | 强制只读 | 如确需写入，发送新的明确任务 |
| N24 | 同项目已有写任务 | 新任务排队，不并发写 | 等待、停止前一任务或在另一项目工作 |
| N25 | 排队期间角色、ACL、策略或 sandbox 上限变化 | 启动前失败关闭 | 恢复授权后重新发送，不自动复活旧授权 |
| N26 | 运行中 Bridge 中断 | 任务标记中断，保留 thread/基线/已发现变更 | 先审阅工作区，再人工重试 |
| N27 | 重复消息事件或 callback | 第二次由幂等层忽略 | 无需恢复；若已重复执行按 S1 处理 |
| N28 | 飞书 429/5xx/网络重置/超时 | 有界重试；终态失败时可靠降级 | 网络恢复后由用户重试或 outbox 补发 |
| N29 | commit/push/publish/release/deploy/PR/MR | 进入短期确认，不随普通任务执行 | 所有者在有效卡片确认，或取消 |

## 5. 设备与连接失败（N30～N34）

| 编号 | 触发条件 | 产品表现 | 恢复动作 |
|---|---|---|---|
| N30 | 消息消费者未 ready | 控制台显示连接中/降级和绝对采样时间 | 检查应用事件、网络和服务日志；恢复后只发一次去重通知 |
| N31 | 卡片消费者未 ready | 禁用依赖 callback 的控件，不声称完全在线 | 修复卡片事件并重新发布应用版本 |
| N32 | 两个消费者都离线 | 不接收任务，不展示虚假可执行 | 本机恢复网络/服务后让用户重发未确认消息 |
| N33 | Codex app-server 不可用 | 设备在线但引擎异常，任务不启动 | 完成 Codex 登录、重连或重启 Bridge |
| N34 | 健康文件 PID/配置/实例不一致 | 安装或 status 失败关闭 | 停止错误实例，用目标配置重新 install 并验证双消费者 |

## 6. 项目选择与项目状态失败（N35～N40）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N35 | 项目列表找不到目标 | 不允许输入任意未授权目录 | 配置 `CODEX_PROJECT_ROOTS` 或重新运行向导并重启 |
| N36 | 同名项目选错风险 | 强制显示路径和 Git 状态 | 取消选择，按绝对路径重新确认 |
| N37 | 无项目 ACL | 项目从列表、历史和搜索隐藏，任务拒绝 | 管理员更新 ACL 后重新进入 |
| N38 | 私聊切换时有任务/队列/上下文 | 显示影响确认，不立即切换 | 等待/停止任务，或确认解绑 thread 和撤销租约 |
| N39 | 项目目录被移动或删除 | 绑定保留，任务失败关闭 | 恢复原路径；迁移必须由管理员受控完成 |
| N40 | Git 状态采集失败或非 Git 项目 | 仍可使用，但标记归因未知 | 修复 Git，或接受原生文件事件的有限证据 |

## 7. 会话、队列和进程恢复失败（N41～N46）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N41 | 保存的 thread 不存在或不可恢复 | 不创建伪装成原会话的新 thread | 新建会话，并在首条消息补充必要背景 |
| N42 | 模型或推理能力与旧会话不兼容 | 使用可验证回退并提示 | 在设置中选择当前支持组合后继续 |
| N43 | 同一会话并发两项工作 | 后一项排队 | 在新话题创建独立会话，或等待当前任务 |
| N44 | 队列满或等待超时 | 明确队列位置/超时原因，不丢任务事实 | 停止无用任务或稍后重新发送 |
| N45 | 停止任务后仍有文件变更 | 明确“停止不等于撤销” | 查看验证/Git 状态，发送新的修复要求 |
| N46 | 启动恢复时任务状态与卡片冲突 | 保守对账：显式终态优先，启动证据优先于排队 | 更新 SQLite/可更新卡片并写审计，不重放状态不明任务 |

## 8. 模型、推理、sandbox 和额度失败（N47～N54）

| 编号 | 触发条件 | 产品表现 | 恢复动作 |
|---|---|---|---|
| N47 | 模型目录暂时不可用 | 设置卡进入只读兼容模式 | 保留已有设置，目录恢复后刷新 |
| N48 | 已保存模型被移除 | 本任务安全回退并说明 | 选择当前模型，或恢复“Codex 默认” |
| N49 | 推理强度不受当前模型支持 | 回退到支持档位，不崩溃 | 在模型控制中心重新选择 |
| N50 | 问答/分析请求了写权限 | sandbox 被钳制为只读 | 如需修改，发送新的明确写入任务 |
| N51 | 完全访问租约过期/用完/切项目或 thread | 自动恢复安全默认 | 成员为新的范围重新申请 |
| N52 | 仓库策略无效、过大、符号链接或含未知动作 | 整个策略失败关闭，任务不启动 | 修复根目录普通 JSON 并重新发送任务 |
| N53 | 额度接口不可用 | 显示不可用，不展示伪造百分比/预计时间 | 检查 Codex 账号和连接后刷新 |
| N54 | 任务超出真实额度或限流窗口 | 任务失败或等待 Codex 返回，不自动换账号/模型 | 等窗口重置，或由成员显式选择可用模型 |

## 9. 运行环境与安装状态失败（N55～N61）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N55 | 配置文件已存在且含未知高级键 | 向导备份并只合并已知键 | 审阅预览；只有明确重建才用 `--force-reset` |
| N56 | 初始化中断 | 保存非敏感检查点，不写虚假完成 | 重新运行 `init` 从安全步骤恢复 |
| N57 | 配置/数据权限过宽 | doctor 失败或警告 | 运行 `doctor --fix`，复核为目录 0700、文件 0600 |
| N58 | 测试卡发送失败但服务健康 | 安装状态与测试卡状态分开显示 | 修复飞书回复能力后重发测试，不重装服务 |
| N59 | 本机睡眠、关机或断网 | 飞书只能显示最后采样状态 | 回到本机恢复电源/网络，重发未确认任务 |
| N60 | Remote Ready 进程异常 | 控制台显示关闭或异常 | 管理员显式关闭再开启；不绕过系统策略 |
| N61 | VPN/公司网络依赖不可用 | 相关任务失败并保留本地状态 | 恢复受信网络后重新执行，禁止把凭据发到飞书 |

## 10. Codex 追问、审批和外部动作失败（N62～N68）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N62 | 问题/审批卡过期 | 控件失效并说明状态 | 从任务卡刷新当前请求，或重新发起任务 |
| N63 | 问题/审批被重复点击 | 只消费第一次 | 后续点击显示已处理，不再次恢复 turn |
| N64 | 非所有者/非控制者处理交互 | 拒绝并记录越权审计 | 先完成合法任务交接，再处理仍有效请求 |
| N65 | Codex 请求秘密 | 卡片无回答通道，日志只留脱敏占位 | 取消远程回答，回可信本机输入 |
| N66 | “本会话允许”缺少二次确认 | 不授予会话范围 | 重新打开有效审批并明确确认 |
| N67 | 外部动作确认到期或动作内容改变 | 旧确认失效 | 基于最新动作生成新确认；不得沿用旧授权 |
| N68 | 仓库策略在确认后、执行前变严 | 执行前重新验证并拒绝 | 按新策略修改要求后重新申请 |

## 11. 结果、审阅和测试失败（N69～N74）

| 编号 | 触发条件 | 产品表现 | 恢复动作 |
|---|---|---|---|
| N69 | Git 基线失败/非 Git/旧任务 | 标记“归因未知”，不声称 Diff 完整 | 本机检查，必要时新任务前恢复 Git |
| N70 | 工作区任务前已脏且被再次修改 | 文件标记“混合” | 人工区分既有变更与任务变更，不一键丢弃 |
| N71 | 最后一次测试失败 | 任务卡使用失败视觉 | 修复后重跑测试；最后一次真实证据决定当前状态 |
| N72 | 没运行测试 | 明确“未检测到测试命令” | 用户决定是否要求补测，不把完成当通过 |
| N73 | 文件在任务后继续变化 | Diff 显示过期 | 刷新快照或回本机审阅最新内容 |
| N74 | Diff/测试摘要命中敏感路径或秘密 | 只展示类型/脱敏文本 | 回本机可信环境查看；按 S0 判断是否撤销凭据 |

## 12. 附件失败（N75～N77）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N75 | 附件过大、过多或类型不支持 | 任务不读取该附件并说明限制 | 压缩、拆分或转换为受支持格式后重发 |
| N76 | 飞书附件下载失败/链接过期 | 不把空文件交给 Codex | 重新上传并发送新的任务消息 |
| N77 | 缓存清理或权限失败 | 不泄漏缓存路径，不删除飞书原文件 | 管理员修复私有数据目录并运行安全清理 |

## 13. 项目群远端异常（N78～N80）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|
| N78 | 群被删除或机器人被移出 | 保留不可变绑定并显示远端不可用 | 管理员确认远端事实；显式重建流程成熟前不自动建第二群 |
| N79 | 群被重命名或成员被人工修改 | 绑定不变，状态按远端重新同步 | 管理员按 ACL 重新同步成员/工作台 |
| N80 | 群内要求切换到另一个项目 | 拒绝切换并指向正确项目群 | 创建/进入另一个项目群，不改当前绑定 |

## 14. 团队协作失败（N81～N86）

| 编号 | 触发条件 | 安全终态 | 恢复动作 |
|---|---|---|---|

## 恢复后的统一验收

每个故障关闭前必须确认：

1. **状态真实：** 飞书 UI、SQLite、本机和必要的飞书远端对象一致。
2. **没有重复：** 群、工作台、任务、审批、外部动作和发布次数没有增加。
3. **没有串线：** 成员、项目、会话、thread、附件和权限仍在原作用域。
4. **没有放权：** ACL、sandbox、仓库策略和临时租约没有因恢复被放宽。
5. **没有隐式重放：** 已启动或状态不明任务只能由用户审阅后人工重试。
6. **数据可恢复：** SQLite 完整性通过；迁移/升级类故障有可验证备份 ID。
7. **信息已脱敏：** 卡片、日志、outbox、诊断包、Diff、测试摘要和公开 Issue 无秘密与私有标识。
8. **证据已记录：** 故障编号、根因、修复步骤、验收人和时间可追溯。

任一项不满足，故障仍处于处理中，不能以“重新点一下能用了”作为关闭标准。
