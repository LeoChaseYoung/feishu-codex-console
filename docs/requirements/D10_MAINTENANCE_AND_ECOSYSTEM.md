# D10 维护与开源生态

## 1. 用户问题

Feishu Codex Console 会长期运行在真实开发机上。安装者需要在不理解源码、不丢失队列和会话的前提下升级、诊断和回退；维护者需要确定发布物与运行时依赖一致；贡献者需要从一个清楚、可测试的小改动进入项目。

## 2. 产品目标

1. 一条命令看懂版本与兼容性，一条命令生成脱敏支持包。
2. 升级默认只预览；执行前备份，执行后验证，失败尽可能自动回退。
3. 配置、状态、SQLite、仓库策略和运行手册都有显式版本。
4. npm tarball 是真实安装单位，而不是只能从维护者源码目录运行。
5. 贡献者只根据公开文档即可完成检查、打包和提交。

## 3. 已确认产品决策

- 稳定版采用 Semantic Versioning。`1.x` 保证已文档化 CLI、配置 v1、策略 v1、运行手册 v1 和自动状态迁移；内部 TypeScript 模块不承诺为公共 API。
- npm 包精确固定 `@openai/codex` 与 `@larksuite/cli`。升级依赖必须经过跨平台、tarball 和真实飞书/Codex 验证。
- 当前不开放插件 API。扩展点先保持为内部适配边界，直到飞书核心协议和安全模型稳定。
- 其他 IM/Agent 适配器暂不进入主包；未来需保持核心任务域与传输层解耦后再独立评估。
- 默认不收集匿名遥测。安装、任务和恢复指标只保存在本地；未来遥测必须显式选择加入且不含代码、提示词、Diff、身份 ID 或路径。
- 一个 npm 包升级一个本机实例。多设备编排不与本地包升级混在一起。

## 4. 版本契约

| 契约 | 当前版本 | 不兼容处理 |
|---|---:|---|
| 配置文件 | 1 | 未填写按 v1；未知未来版本拒绝启动 |
| 持久状态 | 6 | 逐版本迁移；迁移前备份；失败恢复 |
| SQLite schema | 1 | `PRAGMA user_version` 校验和事务化迁移 |
| 仓库策略 | 1 | 整份失败关闭 |
| 运行手册 | 1 | 整份失败关闭，替换参数后再次检查 |
| 健康文件 | 1 | 安装器只接受已知健康格式 |

新增环境变量必须有安全默认值，并同步 `.env.example`、配置参考、向导和测试。删除或重新解释配置键需要主版本和迁移说明。

## 5. 安全升级状态机

```text
读取当前健康与版本
  → 有活动任务：拒绝
  → 无 --yes：只显示计划
  → 创建并校验 SQLite 备份
  → 用目标包运行 doctor
  → 停止旧服务
  → 安装目标包
  → 等待 PID、配置、心跳和两个飞书消费者
  → 版本一致：完成
  → 任一步失败：停止失败服务 → 恢复数据 → 恢复可用旧服务 → 报告备份 ID
```

排队但从未启动的任务保留在 SQLite，升级后按 D8 规则重新授权和恢复。运行中任务不会为升级被静默中断；操作者必须先等待或显式停止。

如果旧 npm 临时目录已被清理，工具仍恢复数据并尝试启动当前可用包，但必须明确提示无法保证旧包二进制回退。手工 `backup` / `backups` / `rollback` 始终保留。

## 6. 诊断与支持

- `version --json`：产品、Node、固定依赖、配置/状态/SQLite 和平台契约。
- `doctor`：只读检查；`doctor --fix` 只修复文件权限、过期健康标记和日志容量。
- `support-bundle`：默认写入私有数据目录的脱敏 JSON，不覆盖已有文件。
- Issue 模板要求版本、平台、最小复现和人工复核后的支持包；禁止上传数据库、凭据和真实身份。

支持包是诊断辅助，不是匿名遥测，也不会自动上传。

## 7. 发布门禁

1. tag、`package.json` 和 Release 版本完全一致。
2. Ubuntu 与 macOS 完成 `npm ci`、typecheck、全部测试、构建和真实 tarball 安装。
3. tarball 验证双 CLI、断点安装恢复、配置权限、运行手册初始化和升级只读预览。
4. 兼容性文档必须和固定依赖、配置/状态/SQLite 版本一致。
5. 预发布使用 npm `next` dist-tag；稳定版使用 `latest`。
6. 发布前完成真实 macOS、Linux、飞书成员角色、任务交接、审批、审阅和恢复清单。

## 8. 开源贡献路径

- `README.md` 提供中文产品和安装入口，`README.en.md` 提供完整英文入门路径。
- `CONTRIBUTING.md` 给出代码地图、检查命令和高风险变更要求。
- `ROADMAP.md` 公开现在、下一阶段、后续和明确非目标。
- Good First Issue 只选择不需要真实凭据、范围单一、有自动验收的工作。
- 安全漏洞通过私有 Security Advisory；授权绕过、凭据泄漏和命令策略逃逸不得公开披露。

## 9. 验收标准

- [x] 配置存在显式 v1 合约，未知未来版本拒绝加载。
- [x] 版本命令报告固定依赖和数据合约。
- [x] 支持包使用现有脱敏 doctor 输出并写入私有目录。
- [x] 升级无 `--yes` 不修改系统；有活动任务时拒绝。
- [x] 执行升级前生成校验备份，成功后验证健康与产品版本。
- [x] 失败路径恢复数据，并在旧包仍存在时验证旧服务。
- [x] 运行手册可从已安装 npm 包初始化且不覆盖团队文件。
- [x] tarball 测试覆盖安装恢复、运行手册和升级预览。
- [x] 发布门禁验证兼容性文档与包清单。
- [x] 中英文入口、配置、兼容性、演示、Roadmap 和贡献入口齐全。
- [ ] 发布候选版本完成一次干净 macOS 和 Linux 实机升级/降级演练。
- [ ] 建立真实 GitHub `good first issue`，并由外部贡献者完成一次文档或纯测试 PR。

## 10. 后续版本

- `runbooks validate` 与本地 JSON Schema。
- 支持包在飞书中生成前的字段预览和选择性导出。
- 本地、明确 opt-in 的安装/首任务可靠性统计。
- 多设备中心控制面的独立协议、版本协商和代理升级设计。
- 核心任务域成熟后，再评估稳定 adapter SDK；不直接暴露安全关键内部对象。
