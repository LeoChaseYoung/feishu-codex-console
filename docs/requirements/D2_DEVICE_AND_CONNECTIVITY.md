# D2：设备与连接状态

状态：`beta.4` 闭环已完成
范围：`beta.4` 设备可用性闭环
日期：2026-07-16

## 1. 产品目标

用户在飞书打开控制台后，5 秒内能判断这台本地设备现在是否适合执行 Codex 任务；异常时能看到原因、状态采样时间和下一步动作，而不是把旧卡片误认为实时在线证明。

## 2. 已确认决策

- 第一版一个桥接实例只代表一台设备；多设备路由留到存在中心控制面之后。
- 状态卡必须显示绝对采样时间和本人最后一次成功任务时间，不显示提示词内容。
- 本地服务已经离线时无法主动更新飞书卡或发送离线提醒；不为此引入公网入站服务，也不伪装成实时云监控。
- 服务恢复后优先更新已有控制台卡，再按会话去重发送一次恢复通知。
- Remote Ready 保持管理员显式开启，不默认开启，也不承诺远程开机或绕过合盖策略。

## 3. 状态模型

| 状态 | 含义 | 是否可发任务 | 卡片动作 |
|---|---|---:|---|
| 在线 | 消息与卡片事件可用，Codex 正常或可按需启动 | 是 | 完整控制 |
| 连接中 | 消息事件尚未就绪 | 否 | 不显示虚假按钮 |
| 部分可用 | 文字消息可用，卡片回调不可用 | 是，建议文字 | 隐藏按钮 |
| 离线 | 健康心跳过期 | 否 | 展示电源/网络/服务恢复说明 |
| 异常 | 飞书在线，但 Codex 最近启动失败 | 否 | 刷新、重连 Codex |
| 维护中 | 服务在线但管理员暂停新任务 | 否 | 查看状态，等待恢复 |

## 4. 核心流程

1. 收到“状态”或控制台卡刷新请求。
2. 汇总消息消费者、卡片消费者、Codex app-server、任务队列、电源和 Remote Ready。
3. 生成唯一权威设备状态与可操作性。
4. 展示采样时间、本人最后成功任务和对应恢复建议。
5. 只在回调链路可用时展示按钮；Codex 异常时提供显式重连。
6. 服务重启恢复后，更新持久化的旧控制台卡并去重通知。

## 6. 非目标

- 远程开机、远程解锁或绕过公司设备策略。
- 在没有外部在线控制面的情况下承诺实时离线推送。
- beta.4 内自动跨多台电脑路由项目和任务。
