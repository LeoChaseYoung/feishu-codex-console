# D6：结果与代码审阅

状态：`beta.4` 闭环已完成
优先级：P0
日期：2026-07-16

## 1. 产品目标

任务结束后，用户只看飞书也能回答三个问题：Codex 改了什么、验证是否通过、哪些内容需要回本机确认。审阅必须区分“Codex turn 正常结束”和“代码已经通过验证”，同时避免把任务开始前的本地修改伪装成本任务产物。

## 2. 已确认决策

- beta.4 继续操作用户当前选中的真实工作区，不默认创建 Git worktree；本机 Codex 和飞书因此看到同一份文件。
- Git 基线在任务真正开始运行时采集，而不是入队时采集，避免排队期间的项目变化被错误归因。
- 工作区干净时，基线之后的变化标记为任务变更；工作区原本有修改时，以文件指纹排除未触碰的既有脏文件，被本任务再次修改的文件明确标记为“混合”。
- 非 Git 项目或基线采集失败时，只展示 Codex 原生文件事件，并明确标记“归因未知”，不声称 Diff 完整。
- 测试证据来自 Codex 实际执行的测试命令、退出码和脱敏输出摘要；同一测试命令多次运行时，以最后一次结果作为当前验证状态。
- Codex turn 完成但最后测试失败时，任务卡使用红色“测试未通过”，不会视觉上呈现为成功。
- 审阅使用飞书 CardKit：文件列表分页，逐文件 Diff 分页。超出安全总量的极大 Diff 截断并提示回本机查看。
- `.env`、私钥、证书、凭据目录等敏感路径只展示存在和类型，不展示正文；普通 Diff 中疑似 Token、密码和私钥块也会脱敏。
- beta.4 不提供“应用修改”，因为 Codex 已直接写入真实工作区；也不提供一键丢弃，避免混合工作区中误删用户原有内容。
- commit、push 和 PR 不是“接受结果”按钮，仍由用户明确提出并经过既有外部动作确认。
- 一个任务只有一张主卡。完成后先显示结果摘要；长回复和验证中心都在原卡内切换并可返回，不再为同一任务堆叠多张结果卡。
- “查看验证”是条件入口：只有存在文件变化或测试证据时才出现；纯分析任务不会进入空审阅页。
- 原任务卡更新成功时默认不另发完成回复；CardKit 更新失败时仍通过可靠回复兜底。
- 如果完整任务卡在创建阶段不可用，轻量兜底卡会保存引用并在排队、运行和终态原地更新；只有兜底卡更新也失败时才新增可靠消息。
- 指向本机绝对路径的 Markdown 链接降级为文件名，外部 HTTP 链接保持可用。

## 3. 审阅流程

```text
任务真正开始
  → 采集 Git HEAD、分支、脏文件与文件指纹
  → Codex 执行，记录命令、测试和文件事件
  → 任务进入终态
  → 生成文件级统计和归因快照
  → 任务卡展示测试/变更结论
  → 原任务卡展示结果摘要
  → 按需在原卡打开“完整结果”或“查看验证”
  → 查看测试证据、文件分页和逐文件 Diff
  → 点击“返回结果”回到摘要
  → 继续发补充要求，或回本机处理敏感/混合/超大差异
```

审阅卡是只读控制面。刷新会重新对比原任务基线，并标记任务结束后又被修改的文件；不会静默更新成“仍属于原任务”。

## 4. 核心状态

### 代码归因

- `task`：任务开始时基线可用，文件没有任务前修改证据。
- `mixed`：至少一个文件在任务开始前已经修改，或基线文件集合过大而无法完整记录。
- `unknown`：非 Git 项目、Git 不可用或旧任务没有运行前基线。

### 测试证据

- `passed`：每个已识别测试命令的最后一次运行均通过。
- `failed`：至少一个测试命令的最后一次运行失败。
- `running`：测试仍在运行。
- `missing`：没有检测到测试命令；任务完成不等于测试通过。

## 5. 验收标准

- 每个新任务在开始时保存可持久恢复的审阅基线，不阻塞非 Git 任务执行。
- 完成、失败、停止和中断任务都生成审阅快照，并保留已发生的代码影响。
- 任务卡明确显示测试状态、文件数量、增删行和归因可信度。
- 最终测试失败时，完成卡不是绿色成功状态。
- 相同测试命令先失败后通过时，当前状态显示通过，同时保留执行历史。
- 未运行测试时明确写“未检测到测试命令”，不推断验证成功。
- 任务前未被触碰的脏文件不会混入任务文件列表；被再次修改的脏文件标记混合。
- 文件列表和单文件 Diff 均可分页；卡片保持在 CardKit 文本和元素限制内。
- 文件在任务后继续修改时，Diff 页面显示过期警告。
- 敏感路径没有正文入口，疑似秘密在测试摘要和 Diff 中统一脱敏。
- 旧卡、跨聊天、跨成员和越权审阅请求被拒绝或安全重建，并写入审计。
- 审阅流程不提供撤销、提交、推送或 PR 的隐式副作用。
- 长结果不会撑满主任务卡；完整结果和验证视图不新增聊天消息。
- 零文件变化且零测试的任务不显示验证入口。
- 原任务卡更新成功时不重复发送完整完成回复；本地路径不会成为远端无效链接。

## 7. 非目标

- 在飞书中实现完整代码编辑器、语法导航或逐行评论系统。
- beta.4 默认创建隔离 worktree 或自动合并回主工作区。
- 一键撤销、`git reset`、丢弃文件或覆盖任务前已有修改。
- 把 Codex 的自然语言总结当成测试通过证据。
- 自动 commit、push、发布、部署或创建/合并 PR。
