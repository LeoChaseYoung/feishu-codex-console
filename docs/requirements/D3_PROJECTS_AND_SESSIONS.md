# D3：项目与会话

状态：`beta.4` 闭环已完成
优先级：P0
日期：2026-07-16

> 2026-07-18 更新：项目群现在是一等工作区。管理员可在已有群首次选择项目，或从私聊一键创建项目群；群与项目首次绑定后不可切换。群聊话题继续作为独立工作会话，详细规则见 [V4 工作区会话交互模型](../V4_WORKSPACE_SESSION_FLOW.md)。

## 1. 产品目标

用户在飞书里发起任务前，能够明确确认本地执行目录、Git 分支、未提交状态和 Codex 上下文；项目重名、收藏排序、服务重启或多人共用时，都不能把任务静默送进错误的目录或会话。

## 2. 已确认决策

- 私聊只有一个当前项目并允许快速切换；项目群首次选择后永久固定项目，不允许任何成员通过卡片或文字命令切换。群内话题各自绑定独立 Codex thread。
- 项目列表始终展示项目名和可辨识路径。用户目录使用 `~` 缩写；重名项目依靠路径区分，不只显示文件夹名。
- 收藏和最近使用按成员保存，不成为团队全局偏好，也不能由管理员替成员修改。
- 收藏优先、最近使用其次；卡片顺序、文字回退列表和 `/use <编号>` 必须使用同一顺序。
- 卡片下拉切换始终显示确认弹窗。文字切换在存在运行任务、排队任务或已保存 thread 时，需要发送 `确认切换 <项目>`。
- 切换项目会停止该飞书会话中的未完成任务，并清空当前保存的 Codex 上下文；不会删除项目文件或 Codex 历史 thread。
- Git 状态只读取当前项目，使用一次有 3 秒超时的只读 `git status`；读取失败不阻塞项目切换。
- 新建 Codex thread 使用首条有效任务自动命名；名称写入 Codex 原生 thread，因此飞书和本机看到同一个名称。
- 团队成员只能看到项目 ACL 允许的项目。历史 thread 默认只展示本人通过桥接创建或恢复的记录；管理员可做受审计的团队排障。

## 3. 核心流程

项目群首次绑定：

```text
管理员把机器人加入已有群，或在私聊点击“一键创建项目群”
  → 按管理员 ACL 展示可用项目
  → 选择并确认一次
  → SQLite 原子写入 chat_id ↔ project_path
  → 群加入运行时可信列表
  → 工作区卡更新并置顶
  → 后续隐藏切换入口，文字切换同样拒绝
```

以下快速切换流程只适用于私聊：

```text
发送“项目”
  → 按成员 ACL 过滤项目
  → 收藏优先、最近使用其次排序
  → 展示当前路径、分支、未提交文件数
  → 搜索或选择目标项目
  → 明确提示运行任务、队列和上下文影响
  → 用户确认
  → 停止当前会话未完成任务
  → 切换项目并清空保存的 thread
  → 记录最近使用并更新原卡片
```

恢复会话：

```text
发送“会话”
  → 只读取当前项目的 Codex thread
  → 应用成员可见性规则
  → 展示名称、最近更新时间和任务摘要
  → 用户选择并确认恢复
  → 停止当前未完成任务
  → 保存选中的原生 thread ID
  → 下一条任务通过 thread/resume 继续
```

## 4. 交互与数据规则

### 项目标识

- 卡片当前项目区同时展示名称和 `displayPath`。
- 下拉选项同时包含名称、类型和路径，并对收藏、最近使用增加视觉标记。
- 最多在卡片展示 100 项；超过上限时，文字命令仍可按名称或路径搜索全部授权项目。
- 模糊匹配到多个项目时返回候选名称和路径，不自动选择第一个。

### Git 状态

- 展示当前分支或 detached HEAD。
- 展示未提交文件数量以及相对上游的 ahead/behind。
- 不执行 fetch，不访问网络，不改变 index，也不持有 Git 锁。

### 收藏与最近使用

- 唯一键为 `owner_id + project_path`。
- 最近使用在切换和实际创建任务时更新。
- ACL 撤销后，对应项目立即从列表、收藏和最近使用结果中消失；保留本地偏好行以便恢复授权后继续使用。

### 会话

- 新 thread 名称取首条任务的第一行，清理 Markdown 前缀并限制长度。
- 会话中心使用 Codex 原生 name/preview/updatedAt，不复制完整对话到桥接数据库。
- 项目切换只解除当前飞书会话的 thread 绑定，不归档或删除原生 thread。

### 飞书与本机 Codex 双向接力（V4 后续）

当前边界必须对用户说清楚：

- 桥接层把真正交给 Codex 的提问、附件和后续补充写入原生 Codex thread。
- 飞书卡片、按钮、状态通知、任务元数据和无关群消息不会复制进 Codex 对话。
- 在同一台设备、同一 Codex 账号与数据目录下，本机 Codex 可以恢复这个原生 thread；它不会自动打开，也不会天然标记为“来自飞书”。
- 本机继续同一个 thread 后，飞书下一轮恢复该 thread 时应继承新增上下文；本机另开 thread 时，飞书不得猜测或自动切换。

目标交互：

1. 飞书工作会话始终展示可读会话名、项目和来源，并把内部 thread ID 收进详情。
2. 工作区控制卡提供“在 Codex 中打开”，将本机 Codex 导航到同一个原生 thread。
3. 私聊首页与会话中心可选择“继续飞书会话”或绑定一个本机已有 thread，绑定前必须确认项目一致。
4. 两端显示最近活动来源（飞书 / 本机）和更新时间，避免用户误以为所有飞书消息都已同步。
5. 同一 thread 的上下文只保存一份，不复制完整聊天记录到桥接数据库。

## 5. 验收标准

- 同名项目在所有选择入口都能通过路径辨识。
- 收藏或最近使用改变排序后，`/use 1` 与列表第 1 项保持一致。
- 存在任务、队列或保存上下文时，普通文字切换不会立即执行。
- 项目卡能展示当前 Git 分支和未提交文件数；非 Git 目录不显示伪造状态。
- 无权项目不会出现在卡片、文字回退、模糊搜索、最近使用或会话历史中。
- 收藏按成员隔离，管理员不能通过他人的卡片修改其偏好。
- 服务重启后当前项目、收藏、最近使用和 thread 绑定仍然存在。
- 已有群首次绑定后服务重启仍保持相同项目；重复选择、文字切换和绑定到已占用项目都被拒绝。
- 新建 thread 获得可读名称，恢复后下一轮继续同一个 thread ID。
- 双向接力完成后，从飞书打开本机 Codex 必须落到同一个 thread；在任一端继续后，另一端恢复时能读到新增的 Codex 上下文。
- 飞书控制消息与普通群聊内容不得伪装成已同步的 Codex 对话；另开本机 thread 不得改变飞书绑定。

## 7. 非目标

- 通过飞书输入任意绝对路径并把它注册成项目。
- 在项目卡内实现完整 Git 分支管理、提交、拉取或合并。
- 删除、归档或跨项目搬运 Codex 原生 thread。
- 在 `beta.4` 引入云端项目索引或多设备项目路由。
